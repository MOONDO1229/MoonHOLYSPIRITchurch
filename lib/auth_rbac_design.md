# 🔐 관리자 권한 구조(RBAC) 설계 및 발전 방향 (TODO)

현재 시스템은 단일 관리자 계정 체제입니다. 향후 교회 규모 확장 및 다중 사용자 운영을 위해 다음과 같은 권한 구조를 설계합니다.

---

## 1. 역할별 권한 정의

| 역할 (Role) | 권한 범위 | 접근 제한 항목 |
| :--- | :--- | :--- |
| **최고관리자 (Super Admin)** | 시스템 전체 권한 | 없음 |
| **콘텐츠 관리자 (Manager)** | 모든 콘텐츠 CRUD | 사이트 설정, 관리자 계정 관리 |
| **사무실/교역자 (Staff)** | 공지, 주보, 예배시간 | 설교 관리, 팝업 관리, 설정 |
| **미디어 담당 (Media)** | 설교, 팝업 포스터 | 주보 관리, 사이트 설정 |
| **작성자 (Editor)** | 본인 작성 글 수정 | 삭제 권한, 승인 권한 |

---

## 2. 데이터 구조 제안 (DB 전환 시)

```json
// users.json 또는 users 테이블
{
  "id": "admin_user_1",
  "name": "홍길동 목사님",
  "role": "staff",
  "permissions": ["notices.write", "bulletins.write"]
}
```

---

## 3. 구현 단계별 로드맵

### 1단계: 환경변수 기반 다중 계정 (간이 방식)
- `.env.local`에 JSON 형태로 여러 계정 정의
- 로그인 시 해당 계정의 Role을 세션 쿠키에 저장

### 2단계: Middleware 권한 체크
- `middleware.js`에서 특정 경로(예: `/admin/settings`) 접근 시 `admin` 역할인지 검증

### 3단계: DB 기반 완전한 RBAC (추천)
- Supabase Auth 또는 NextAuth.js 도입
- 사용자 테이블에서 정교한 권한 매트릭스 관리

## 4. UX 최종 점검 결과 (Sprint 4)

- **글자 크기**: 모바일 본문 18px 이상 적용 확인. (globals.css 점검 완료)
- **터치 영역**: 모든 버튼 높이 56px, 팝업 닫기 48px 이상 확보.
- **가독성**: 예배시간 카드 UI에서 '시간'과 '장소'에 고대비/굵은 글씨 적용.
- **반응형**: iPhone SE 등 작은 화면에서 가로 스크롤 발생하지 않음 확인.
